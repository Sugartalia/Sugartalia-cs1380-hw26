==================== Part A ====================

1. fopen returns NULL if it fails. Before I use the FILE pointer,
   I check that it isnt NULL. If it is, I use perror to print the
   error and return or exit instead of trying to use it.

2. "r" opens an existing file for reading (like when I read out.txt).
   "w" opens a file for writing and either creates it or erases
   what was already in it (like when I write out.txt).
   "rb" and "wb" are the binary versions, which I used for records.bin.

3. Every successful fopen opens a file handle and uses buffered data.
   fclose flushes the buffer and closes the file. If I forget to do
   it before an early return, I could lose data or leave the file open.

   In text_copy.c, if the output fopen fails, I still fclose the
   input file before returning.


==================== Part B ====================

4. fgets is better when I want to read a whole line, including spaces.
   fscanf with %s stops at whitespace, and if I dont give it a width
   limit it could overflow the buffer. fgets also takes the buffer size,
   so its safer.

5. fwrite copies the actual bytes of the struct in memory, so it is
   fixed size and not really readable by a person.

   fprintf writes the fields as text, so someone can actually read it.
